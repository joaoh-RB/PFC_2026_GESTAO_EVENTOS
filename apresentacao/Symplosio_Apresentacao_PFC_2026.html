O problema

O que o Symplosio soluciona

Centraliza divulgação, inscrição e gestão de eventos acadêmicos em um único fluxo digital, com papéis claros e rastreabilidade.

1

Divulgação fragmentada

Eventos espalhados em murais, grupos e planilhas, sem um canal oficial da instituição.

2

Inscrição e presença manuais

Controle difícil de vagas, listas de presença e confirmação de participação.

3

Gestão sem rastreio

Grupos, documentos e aprovações sem histórico claro entre os diferentes perfis.

4

Falta de visão gerencial

Instituições sem indicadores consolidados de engajamento e acompanhamento acadêmico.

Stack

Tecnologias utilizadas

Front-end, back-end e serviços em nuvem integrados para um monólito em camadas pronto para demonstração e evolução.

Front-end

  • React 19 + TypeScript + Vite
  • Tailwind CSS 4 + shadcn/ui
  • React Router 7
  • React Hook Form + Zod
  • Axios, Recharts e xlsx
  • Hospedagem na Vercel

Back-end

  • .NET 10 + C#
  • Entity Framework Core + Npgsql
  • FluentValidation + Swagger
  • xUnit + Moq
  • JWT em cookie HttpOnly
  • Hospedagem no Render (Docker)

Serviços

  • Supabase — PostgreSQL e arquivos
  • SendGrid — envio de e-mails
  • Google Calendar — sincronização
  • Vercel — front-end
  • Render — API
  • CI com testes automatizados

Arquitetura

Monólito em camadas

Uma API .NET organizada por responsabilidades, consumida pelo front React — simples de operar e clara para evoluir.

C
Controllers Endpoints HTTP · JWT · autorização por perfil
A
Application Services · DTOs · FluentValidation · regras de negócio
D
Domain Entidades · enums · Value Objects · herança TPH de usuários
I
Infrastructure EF Core · Repositories · SendGrid · Google Calendar · Supabase

Deploy

  • Front-end → Vercel
  • API monólito → Render (Docker)
  • Dados e arquivos → Supabase

Por que camadas?

Isola o domínio da infraestrutura, facilita testes unitários e mantém o fluxo Controllers → Application → Domain / Infrastructure previsível.
